# Security model and feasibility gate

Third-party source and its browser JavaScript are hostile. This system provides static delivery with layered isolation, not malware certification or a general-purpose secure compute platform.

## Boundaries implemented

1. The control plane accepts canonical HTTPS `github.com` repo/tree/commit URLs only. Credentials, ports, query/fragment, host tricks, traversal and command injection are rejected. GitHub metadata requests are fixed to `api.github.com`, without redirects. Public visibility and a 40-character immutable SHA are checked server-side. Branch names with slashes resolve using longest valid prefix. Source/archive/file counts and sizes are bounded; LFS and submodule execution are disabled.
2. One SQLite-backed personal coordinator atomically reserves queued/active jobs before external I/O. Fingerprints include canonical source, SHA, app root, lock digest, normalized config and adapter/toolchain version. GitHub dispatch is never blindly retried after ambiguous network results. Dispatch uses a protected release tag (the documented GitHub API contract), with a separate expected immutable SHA. Current API run IDs are persisted when returned; older 204 responses fall back to exact reconciliation. Matching uses workflow path, event, trusted orchestration head SHA, exact job title, generation and attempt=1; callback verifies the same binding against GitHub. No source auto-sync exists.
3. `build-untrusted.yml` has workflow permissions `{}`, job `contents:read` only for checkout of the private trusted orchestrator, `persist-credentials:false`, no environment/secrets reference, no dependency cache, no self-hosted runner. Source is fetched publicly by SHA without authentication. Build subprocess env is rebuilt from a small non-secret allowlist. Third-party install/build is confined to this disposable runner. GitHub artifact-service runtime credentials necessarily exist on Actions runners; a malicious process could misuse its job's artifact capabilities/read-only token. They cannot obtain the publisher's environment secrets from this workflow. Runner egress is not fully restricted; do not claim a strong network sandbox.
4. The separately dispatched publisher runs on a fresh runner and checks out only the immutable trusted orchestration commit. It uses Python stdlib, never installs/imports/executes target code, and never extracts an archive into its checkout. ZIP and tar checks bound compressed/uncompressed sizes, file counts, duplicates, traversal, links, devices, executable modes, checksums, exact manifest file set and MIME extensions. `_worker.js`, `functions/`, startup scripts, hidden files and unknown asset types are rejected. Manifest fields bind to the stored source/config/job. HTML/JS are passive for this job and remain untrusted when served in the browser.
5. R2 is private; no `r2.dev`/public custom domain. Only the Preview Worker reads site bytes publicly. PreviewAccess is a separate, narrow service entrypoint exposing only prefix/SPA/expiry, not admin API. Every preview asset/HTML/HEAD request checks the DO and checks again after R2 I/O. Expire/delete returns 410 even while bytes remain. All preview responses use no-store (including CDN); do not add cache rules that bypass this Worker. Already downloaded bytes/in-flight responses cannot be erased from a visitor's machine.
6. Admin cookie is host-only `__Host-`, Secure, HttpOnly, SameSite=Strict, 12-hour expiry. Opaque random token is stored as SHA-256 server-side; logout deletes it. State changes require exact configured Origin, non-cross-site fetch context and per-session CSRF header. No admin CORS permissions are sent. Preview scripts cannot read cookie/body/CSRF across origins. Admin dashboard gets noindex, CSP, frame protection and no third-party runtime scripts/fonts.
7. PBKDF2-SHA256 600,000 iterations, random salt, 256-bit hash. Configured hash parameters are validated, never downgraded to pass Free CPU. `password:hash` benchmarks local wall time. **Local success is not a Worker Free CPU benchmark.** AUTH_CPU_VERIFIED defaults false and must remain false until deployed CPU measurements permit the chosen KDF. Test at least success/failure login and rate-limited attack traffic. If account CPU limits reject it, leave login disabled and choose an explicitly reviewed authentication/plan change. Rate limits reserve attempts before KDF: 5/IP and 20 global in 15 minutes; IP keys are HMAC hashed. No dev bypass is compiled into production.
8. Internal callbacks/plans use HMAC-SHA256 over exact `timestamp.nonce.body`, five-minute skew and persistent nonce consumption. Secrets are separate: orchestration PAT, callback secret and bucket-scoped R2 key pair. Logs redact token/credential-like values; password bodies and environment dumps are never logged. Signed artifact redirect downloads strip GitHub Authorization.
9. Iframes use a separate origin and `sandbox=allow-scripts allow-forms allow-same-origin`, no top navigation/popups/downloads, no camera/mic/geolocation. Preview CSP blocks Worker/service-worker registration, objects and embedding outside configured dashboard. Clear-Site-Data clears persistent storage. Wildcard route mode gives each preview an origin. Fallback path mode shares a preview origin across previews, so it has weaker sibling isolation; never enter sensitive data. No admin session lives on that host.
10. Browser validation is secretless, new contexts, service workers blocked, GET/HEAD only, request cap 120, same-preview-origin outbound requests only. No destructive clicks or third-party login/payment. Screenshots and report are passively checked/uploaded by a fresh trusted report job. External API-dependent apps may honestly be partial.

## Release gates

Local tests prove URL/manifest negatives, auth/CSRF/logout/rate limits, direct expiry/revocation, private bucket delivery, queue/dedupe, run/callback binding and fixture browser QA. Workflow policy tests inspect privileged separation. These do not prove GitHub/Cloudflare account configuration. Before enabling arbitrary builds: review Actions environment scope/branch rules, verify disposable runners and permissions, test real public repositories, attempt malicious artifacts, verify public R2 is off, verify origin/DNS/TLS and measure KDF CPU. Keep `BUILDS_ENABLED=false` when any gate fails.

**Dynamic full-stack gate remains closed.** No third-party Worker code is deployed into an account/bindings containing dashboard secrets. Static registry is extensible, but runtime adapters require a separate reviewed isolation design and explicit admin approval.
